# Patch map

Every Harmony patch in this mod: the vanilla method, the mod class and what it does. Keep one row per vanilla method (or group of panel methods) and update it with every patch change.

| Vanilla method | Mod class | Purpose |
|---|---|---|
| `MedicalCondition.UpdatePossibleDiagnoses` | `MedicalCondition_UpdatePossibleDiagnosesPatientContext` | Exposes the patient to `GetPossibleDiagnoses`, which has no patient parameter, via `[ThreadStatic] DiagnosisPatientContext` |
| `MedicalCondition.GetPossibleDiagnoses` | `MedicalCondition_GetPossibleDiagnoses` | Log-likelihood scoring (replaces vanilla) |
| `MedicalCondition.IsClear(float,int)` | `MedicalCondition_IsClearWithCertaintyThreshold` | Uses `m_probabilityWeighted` |
| `MedicalCondition.Diagnose` | `MedicalCondition_Diagnose` | NPC diagnoses early only with enough positive evidence |
| `ProcedureComponent.GetAllExaminationsForMedicalCondition` | `ProcedureComponent_GetAllExaminationsForMedicalCondition` | Keep only exams that reveal a hidden symptom of a possible diagnosis, plus interview, Differential Diagnosis and surgery complications. Clears stale availability during UpdateAll |
| `ProcedureComponent.UpdateAllExaminationsForMedicalCondition` | `ProcedureComponent_UpdateAllExaminationsForMedicalCondition` | Sorts the availability map by relevance |
| `ProcedureComponent.SelectExaminationForMedicalCondition` | `ProcedureComponent_SelectExaminationForMedicalCondition` | NPC weighted exam choice |
| `DiagnosisPanelController.UpdateDiagnoses`, `ExaminationsPanelController.UpdateExaminations/CheckTooltip/UnavailableTooltip`, `SymptomsPanelController.UpdateSymptoms`, `TreatmentPanelController.*`, `TooltipBase.Update` | `HighlightPatches.cs` | Patient context, hover tracking and highlights. One patch class per method, with explicit order |
| `TooltipExamination/TooltipDiagnosis/TooltipSymptom.UpdateData` | `Tooltip*.cs` | Tooltip extensions |
| `BehaviorPatient.SelectNextProcedure` (private) | `BehaviorPatient_SelectNextProcedure` | AI clinic patients: plan and start treatments for collapse-risk symptoms before any exam or transfer; hold in the waiting room (about 1 h) instead of leaving untreated |
| `BehaviorPatient.ObservationCheck` (private) | `BehaviorPatient_ObservationCheck` | At ER diagnosis, skip forced observation when the diagnosis belongs to another existing department, so the AI transfers instead |
| `HospitalizationComponent.TryToStartScheduledTreatment` | `HospitalizationComponent_TryToStartScheduledTreatment` | AI hospitalized: collapse-risk treatments go ahead of a queued surgery. Cancels a surgery reservation and hides surgeries from the skip rule (Prefix `out __state` + Finalizer re-inserts them), for up to 2 h |
| `HospitalizationComponent.UpdateStateBeingTreated` (private) | `HospitalizationComponent_UpdateStateBeingTreated` | AI patient in surgery: resolves a pending collapse with the survival roll (anesthesiologist bonus, no collapse script) and gives collapse-risk treatments instantly |
| `DepartmentManagementLogisticsHybridController.Init` (private), `.UpdateCertaintyUI`, `.UpdateLayout` (private), `.Update` | `DepartmentManagementLogisticsHybridController_Init`, `..._UpdateCertaintyUI`, `..._UpdateLayout`, `..._Update` (`TreatmentThresholdUi.cs`) | `Update` only runs a per-frame check that re-applies the layout if an adjusted element was reset. `UpdateLayout` also has a Prefix (priority 900) that removes our offsets. Compatibility with the Hospital Porters BepInEx plugin (Harmony ID `Loupito75:HospitalPorters`): it snapshots the layout in its own `UpdateLayout` Postfix (priority 0) as "native" and writes "snapshot + its shift" every frame from its `Update` Postfix (priority 0), for every department with a ward. So our Prefix runs before its Prefix (800) to keep its snapshot clean, and our `UpdateLayout`/`Update` Postfixes use `[HarmonyAfter]` + `Priority.Last` so ours go on top. In ward departments our layout is therefore re-applied every frame. Window hierarchy: `LogisticsPanel` (window, top pivot) > `StatisticsPanel` (top-stretched, holds "Certainty / Chief doctor") > `CertaintyPanel` (buttons are center-anchored); `BottomPanel` is a window child positioned by `UpdateLayout`. Radiology and Lab (NoDiagnoses) deactivate `StatisticsPanel` itself while the buttons keep `activeSelf`, so row visibility checks every ancestor. Every layout pass first writes the vanilla value back to every adjusted element, then measures and classifies (above/below/spanning) in that pure vanilla state and re-applies: vanilla `UpdateLayout` on a department switch resets only some values (window height, StatisticsPanel and BottomPanel positions), and a mixed state misplaces the section. New "Treatment" section below the whole Certainty / Chief doctor block (its header starts where the vanilla `BottomPanel` started; placements are classified against the certainty row, since the chief doctor segment's rect reaches past the top of `BottomPanel`): a full-width header cloned from the vanilla certainty header bar (found by its `LocalizedTextController` ID `SEGMENT_HEADING_EMPLOYEES_CERTAINTY`; the bar is the text's parent if that has an `Image` and is not the panel or a container of the buttons; retitled with `MOD_LMSDT_TREAT_HEADER`; spans from the Certainty bar to the Chief doctor bar), and under it the Diagnosis-relevant / Low / Medium / High treatment threshold icons of the active department at vanilla size and spacing, centered on the header. The section is placed in world space. The window is made taller from world positions: every container from the row up to the window grows with its top fixed, and each child is corrected for its own anchors (above the row: stays; below: moves down; large spanning ones: stretch). Tracked as base + offset so vanilla's `UpdateLayout` resets are re-applied once. The vanilla certainty buttons are bottom- or center-anchored in their panel |
| `ProcedureComponent.PlanAllTreatments` | `ProcedureComponent_PlanAllTreatments` | Postfix: AI doctors also plan one non-surgery, non-escalating treatment for each untreated visible symptom at or above the department threshold. Independent of `CriticalTreatments` |
| `BehaviorPatient.TryToStartScheduledTreatment` | `BehaviorPatient_TryToStartScheduledTreatment` (`TreatmentBundling.cs`) | Outpatients: Prefix groups the queue from `treatmentIndex` (all joinable advice and medication together, order chosen by walking cost, collapse-risk medicine first). Never replaces vanilla. Hospitalized patients are grouped by `HospitalizationComponent_TryToStartScheduledTreatment` through `TreatmentBundling.GroupHospitalQueue`, before the vanilla loop, since that loop enumerates the list. The medication-or-advice order of a hospitalized patient is decided only while the assigned doctor `IsFree()` (throttled to once per second per patient), otherwise the current first type is kept. An urgent surgery is a barrier: behind it only urgent treatments are grouped or chained |
| `ProcedureScriptTreatmentPrescription.UpdateStateDoctorStopTalking` | `ProcedureScriptTreatmentPrescription_UpdateStateDoctorStopTalking` | Prefix: after the 5 s item time, a further joinable advice item anywhere in the live queue continues the talking loop (new speech icon, skill points, timer reset, no animation change) |
| `ProcedureScriptTreatmentReceipt.UpdateStateDoctorStopPrescribing` | `ProcedureScriptTreatmentReceipt_UpdateStateDoctorStopPrescribing` | Prefix: same for medication, after the item's typing time (keeps vanilla's 30 s abandon check); applies the per-item nurse-delivery flags via `ApplyReceiptStart` |
| `ProcedureScriptTreatmentReceipt.UpdateStateDoctorPrepareReceipt` (private) | `ProcedureScriptTreatmentReceipt_UpdateStateDoctorPrepareReceipt` | Prefix: a medication added after the last boundary goes back to `DOCTOR_START_PRESCRIBING` before the receipt is printed or saved. Waits for the use component first (so `IsIdle` does not warn), and on a ward re-reserves and re-activates the mobile workstation that vanilla's stop-typing step interrupted |
| `ProcedureScriptTreatmentPrescription.UpdateStateDoctorFinished` (private) | `ProcedureScriptTreatmentPrescription_UpdateStateDoctorFinished` | Prefix: an advice item added after the last boundary goes back to `DOCTOR_START_TALKING`. The 2 s wait only lets the end animation play, so it ends early once both are in place and the doctor is idle (not before 0.5 s) |
| `ProcedureScriptTreatmentPrescription.UpdateStateDoctorStartTalking` | `ProcedureScriptTreatmentPrescription_UpdateStateDoctorStartTalking` | Prefix: the 5 s opening wait is skipped once both are in place and the doctor is idle (not before 0.5 s) |
| `ProcedureScriptTreatmentReceipt.UpdateStateDoctorStartPrescribing` | `ProcedureScriptTreatmentReceipt_UpdateStateDoctorStartPrescribing` | Prefix: the same skip for medication. While the doctor's use component is busy (workstation starting) it waits without calling `IsIdle` |
| `HospitalizationComponent.SelectNextStep` (private) | `HospitalizationComponent_SelectNextStep` | Prefix: acts only on AI ICU patients cleared by a nurse check-up (`IcuStepDown.IsCleared`) with the assigned doctor on shift. Order: not cleared, then vanilla; `GetBlockReason(patient, false)` set, then drop the mark and vanilla; `GetBlockReason(patient, true)` set (busy) or doctor off shift, then keep the mark and vanilla (vanilla re-reserves a doctor at the shift change); otherwise `TryStepDown`. On success the mark is dropped, `__result = true` and vanilla is skipped; on failure (no bed or stretcher) the mark stays and it retries on later steps |
| `HospitalizationComponent.SwitchState` | `HospitalizationComponent_SwitchState` | Prefix (`out __state` = old state) + Postfix: a finished nurse check-up (old `OverridenByNurseCheckUp`, new `InBed`, `m_checkUpTime <= 0.001`) on an AI ICU patient calls `IcuStepDown.MarkCleared` when `GetBlockReason(patient, false)` is null, else `ClearMark` (the newest check-up counts). It never transfers from the Postfix, since the nurse script still calls `FindPatient()` afterwards. The hook is shared with Hospital Care Level Transfer (`Loupito75:HospitalCareLevelTransfer`), which detects completion the same way but excludes the ICU, while ours acts only on the ICU; `__state` is per patch |
| `CharacterPanelController.IsAbleToChangeDepartments` | `CharacterPanelController_IsAbleToChangeDepartments` | Postfix: an ICU patient with no block reason may change department, so the selector opens. Every other vanilla blocker stays |
| `CharacterPanelController.OnDepartmentSelected` | `CharacterPanelController_OnDepartmentSelected` | Prefix (`[HarmonyAfter("Loupito75:HospitalCareLevelTransfer")]`, `Priority.Last`, honours `__runOriginal`): for an ICU patient runs `IcuStepDown.TryStepDown` and the vanilla exam refresh, or plays the forbidden sound with a floating reason. Always skips vanilla for ICU patients. The ordering keeps Hospital Care Level Transfer from seeing the already moved (now HDU) patient |
| `CharacterPanelController.Update` | `CharacterPanelController_Update` | Postfix: for an ICU patient, replaces the tooltip of the big department button only (block reason, min-stay text with hours, or ready). Never touches the small button, whose tooltip Hospital Care Level Transfer saves and restores |

## Config toggles

Settings in `ModSmarterDiagnosisAndTreatment.Config.xml` (registry in `ModConfig.cs`) that switch patches off. "Prepare" means the patch class is not applied at all.

| Setting | Effect |
|---|---|
| `DiagnosisScoring/Enabled` | Prepare: `MedicalCondition_UpdatePossibleDiagnosesPatientContext`, `_GetPossibleDiagnoses`, `_IsClearWithCertaintyThreshold` |
| `NpcDiagnosis/EarlyDiagnosisEnabled` | Prepare: `MedicalCondition_Diagnose` |
| `ExaminationList/FilterEnabled` | Prepare: `ProcedureComponent_GetAllExaminationsForMedicalCondition` |
| `ExaminationList/SortEnabled` | Early return in the `UpdateAll...` Postfix only. Its Prefix/Finalizer always run because they set `UpdatingComponent` for the filter |
| `NpcExamChoice/Enabled` | Prepare: `ProcedureComponent_SelectExaminationForMedicalCondition`. `DeferLowPriorityExamsInEr` gates its ER block |
| `CriticalTreatment/ClinicEnabled` | Prepare: `BehaviorPatient_SelectNextProcedure` |
| `CriticalTreatment/HospitalEnabled` | Return in `HospitalizationComponent_TryToStartScheduledTreatment.Prefix` right after `GroupHospitalQueue`, so bundling still runs |
| `CriticalTreatment/InSurgeryEnabled` | Prepare: `HospitalizationComponent_UpdateStateBeingTreated` |
| `ErObservation/SkipForOtherDepartment` | Prepare: `BehaviorPatient_ObservationCheck` |
| `TreatmentThreshold/Enabled` | Prepare: `ProcedureComponent_PlanAllTreatments` and the four `DepartmentManagementLogisticsHybridController_*` classes |
| `TreatmentBundling/Enabled` | Prepare: `BehaviorPatient_TryToStartScheduledTreatment` and the six `ProcedureScriptTreatment*` classes; `GroupHospitalQueue` returns early |
| `IcuStepDown/Enabled` | Prepare: the three `CharacterPanelController_*` classes, and with `AutomaticForAiPatients` also `HospitalizationComponent_SelectNextStep` / `_SwitchState` |
| `UiHighlights/*` | Early return in each highlight class's track/apply entry points (not in `Restore*`). The `HighlightPatches.cs` classes stay patched, since they also set `PatientPanelContext` for the tooltips |
| `Tooltips/*` | Prepare: `TooltipExamination_UpdateData`, and the `TooltipDiagnosis` / `TooltipSymptom` patches |
