# Patch map

Every Harmony patch in this mod: the vanilla method, the mod class and what it does. Keep one row per vanilla method (or group of panel methods) and update it with every patch change.

| `MedicalCondition.IsClear(float,int)` | `MedicalCondition_IsClearWithCertaintyThreshold` | Uses `m_probabilityWeighted` |
| `MedicalCondition.Diagnose` | `MedicalCondition_Diagnose` | NPC diagnoses early only with enough positive evidence |

| `ProcedureComponent.UpdateAllExaminationsForMedicalCondition` | `ProcedureComponent_UpdateAllExaminationsForMedicalCondition` | Sorts the availability map by relevance |

| `BehaviorPatient.UpdateStateGoingToDoctor` (private) | `BehaviorPatient_UpdateStateGoingToDoctor` (`DoctorCallsPatient.cs`) | Companion of the call fix: a patient who reached the office (no lab specialist) waits while the assigned doctor is `Idle`, still walking and has this patient as `CurrentPatient`. | `Room.SortQueue` | `Room_SortQueue` (`FastTrack.cs`) | Prefix, replaces vanilla: stable insertion sort of the main, lab and units queues by `m_priority` (vanilla tiers), then larger `m_fVisitDuration` (earlier hospital arrival; it freezes only in pharmacy, hospitalization and spawn states), then current order. Non-patients last |
| `BehaviorPatient.CheckNeeds` | `BehaviorPatient_CheckNeeds` (`FastTrack.cs`) | Acts while `FastTrack.IsUrgent`: finished at reception, not sent home, not hospitalized, a visible collapse-risk symptom without an active treatment (planned counts as untreated). Derived from saved data, so nothing is stored. Vanilla runs unchanged when `FastTrack.HasTimeForNeeds` (at least `NeedsQueueAllowance` patients ahead in the main queue; the stable sort restores the place on return). Otherwise Prefix sets `__result = false`, unless a need with a procedure is at or above `NeedsSafetyValve`. Then vanilla runs with every other need above 50 held at 50 (Prefix `out __state`, Finalizer restores), because vanilla takes any need above 50 it can reach, not only the one over the valve. Hospital Patient Life (`Loupito75:HospitalPatientLife`) has a trace-only Postfix here that just reads `__result` |
| `BehaviorPatient.ObservationCheck` (private) | `BehaviorPatient_ObservationCheck` | At ER diagnosis, skip forced observation when the diagnosis belongs to another existing department, so the AI transfers instead |
| `HospitalizationComponent.TryToStartScheduledTreatment` | `HospitalizationComponent_TryToStartScheduledTreatment` | AI hospitalized: collapse-risk treatments go ahead of a queued surgery. | `HospitalizationComponent.UpdateStateBeingTreated` (private) | `HospitalizationComponent_UpdateStateBeingTreated` | AI patient in surgery: resolves a pending collapse with the survival roll (anesthesiologist bonus, no collapse script) and gives collapse-risk treatments instantly |

In ward departments our layout is therefore re-applied every frame. New "Treatment" section below the whole Certainty / Chief doctor block (its header starts where the vanilla `BottomPanel` started; placements are classified against the certainty row, since the chief doctor segment's rect reaches past the top of `BottomPanel`): a full-width header cloned from the vanilla certainty header bar (found by its `LocalizedTextController` ID `SEGMENT_HEADING_EMPLOYEES_CERTAINTY`; the bar is the text's parent if that has an `Image` and is not the panel or a container of the buttons; retitled with `MOD_LMSDT_TREAT_HEADER`; spans from the Certainty bar to the Chief doctor bar), and under it the Diagnosis-relevant / Low / Medium / High treatment threshold icons of the active department at vanilla size and spacing, centered on the header. The section is placed in world space. The window is made taller from world positions: every container from the row up to the window grows with its top fixed, and each child is corrected for its own anchors (above the row: stays; below: moves down; large spanning ones: stretch). Tracked as base + offset so vanilla's `UpdateLayout` resets are re-applied once. The vanilla certainty buttons are bottom- or center-anchored in their panel |

## Config toggles

Settings in `ModSmarterDiagnosisAndTreatment.Config.xml` (registry in `ModConfig.cs`) that switch patches off. "Prepare" means the patch class is not applied at all.

| Setting | Effect |
|---|---|
| `DiagnosisScoring/Enabled` | Prepare: `MedicalCondition_UpdatePossibleDiagnosesPatientContext`, `_GetPossibleDiagnoses`, `_IsClearWithCertaintyThreshold` |
| `NpcDiagnosis/EarlyDiagnosisEnabled` | Prepare: `MedicalCondition_Diagnose` |
| `ExaminationList/FilterEnabled` | Prepare: `ProcedureComponent_GetAllExaminationsForMedicalCondition` |
| `ExaminationList/SortEnabled` | Early return in the `UpdateAll...` Postfix only. Its Prefix/Finalizer always run because they set `UpdatingComponent` for the filter |
| `NpcExamChoice/Enabled` | Prepare: `ProcedureComponent_SelectExaminationForMedicalCondition`. `DeferLowPriorityExamsInEr` gates its ER block |
| `CriticalTreatment/ClinicEnabled` | Early return in `BehaviorPatient_SelectNextProcedure.Prefix` after the lab-room fix (the class is always patched) |
| `CriticalTreatment/HospitalEnabled` | Return in `HospitalizationComponent_TryToStartScheduledTreatment.Prefix` right after `GroupHospitalQueue`, so bundling still runs |
| `CriticalTreatment/InSurgeryEnabled` | Prepare: `HospitalizationComponent_UpdateStateBeingTreated` |
| `FastTrack/PriorityAndQueue` | Prepare: `BehaviorPatient_UncoverSymptomsFromLastExamination`, `_UncoverSymptomsFromLabExamination`, `Room_SortQueue` |
| `FastTrack/SkipNeeds` | Prepare: `BehaviorPatient_CheckNeeds`. `NeedsSafetyValve` is the need level that is still fulfilled; `NeedsQueueAllowance` (0 = off) is the number of patients ahead from which needs work as in vanilla |
| `ErObservation/SkipForOtherDepartment` | Prepare: `BehaviorPatient_ObservationCheck` |
| `TreatmentThreshold/Enabled` | Prepare: `ProcedureComponent_PlanAllTreatments` and the four `DepartmentManagementLogisticsHybridController_*` classes |
| `TreatmentBundling/Enabled` | Prepare: `BehaviorPatient_TryToStartScheduledTreatment` and the six `ProcedureScriptTreatment*` classes; `GroupHospitalQueue` returns early |
| `ExamBundling/BloodDraw`, `/WasteSamples` | Prepare: the blood-draw class and the two urine/stool classes of `ExamBundling.cs`; `CanJoin` also checks the group's toggle |
| `ExamBundling/KeepUndressed` | Prepare: the eight classes of `KeepUndressed.cs` |
| `IcuStepDown/Enabled` | Prepare: the three `CharacterPanelController_*` classes, and with `AutomaticForAiPatients` also `HospitalizationComponent_SelectNextStep` / `_SwitchState` |
| `UiHighlights/*` | Early return in each highlight class's track/apply entry points (not in `Restore*`). The `HighlightPatches.cs` classes stay patched, since they also set `PatientPanelContext` for the tooltips |
| `Tooltips/*` | Prepare: `TooltipExamination_UpdateData`, and the `TooltipDiagnosis` / `TooltipSymptom` patches |

Vanilla fixes without a toggle: the lab-room part of `BehaviorPatient_SelectNextProcedure`, and both classes in `DoctorCallsPatient.cs`.
